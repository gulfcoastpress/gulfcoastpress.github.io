Workflow QA checklist

Every new or changed workflow passes all of this before it is uploaded, published or shared.

1. Import

  • Imports with no errors into a clean local n8n 1.123.x (n8n import:workflow --separate --input=<dir>).
  • Every node type exists in that n8n version (no community or missing nodes).
  • Exported back out, the workflow count matches what went in.

2. Credentials and placeholders

  • No credential IDs, API keys, tokens, real email addresses or real Sheet IDs in the file. Credential blocks have an empty id.
  • Every value the buyer must change lives in one **Config** node and uses an obvious placeholder (REPLACE_..., you@example.com).
  • The Read Me sticky note lists every credential and every Config field.

3. References

  • Every connection points at a node that exists; no orphan nodes (except sticky notes).
  • Every $('Node Name') expression names a node that exists.
  • Every Config field that an expression reads is actually set in Config, and every Config field is used.
  • Every Gmail label or ID the workflow filters on (for example -label:triaged) is also **applied** by the workflow, and has a Config field for its ID.

4. Edge cases

  • AI reply is not valid JSON: the item is skipped (no blank draft, no junk row) and is retried on the next run. It must not be marked done.
  • Dedupe: the same email, lead or source is never processed twice (label applied, sheet column set, or upsert by key).
  • Empty input (no new mail, no rows) ends cleanly without errors or empty emails to customers.
  • Item pairing: code that reads $('X').all()[i] lines up with the current items (no filter between X and here).
  • Anything addressed to a customer is a draft, never an auto-send.
  • Text sent to OpenAI is capped (slice(0, N)), and the model is gpt-4o-mini unless there is a reason.

5. Cost note

  • Estimate tokens per run (prompt characters / 4, plus the input cap, plus expected output) and price it at OpenAI's current gpt-4o-mini rate. Put the per-1,000 figure in the FAQ if it changed.

6. Release

  • Rebuild the guide PDF and the zip from source; check the zip lists every workflow.
  • AI disclosure and no-guarantee line present in guide, README and listing.
  • Add a dated changelog entry.
  • Commit to the private repo; upload or publish only after approval.
